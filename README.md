# 伏线 · SPICE Workbench

**在一张画布上绘制电路、运行 ngspice、摆放波形图，并让可选 AI 助手通过工具参与设计。**

伏线是本地运行的网页电路仿真工作台，使用 React、TypeScript、Vite 和 WebAssembly 版 ngspice。它尝试把桌面原理图工具的交互和网页工作台结合起来：画电路、放探针、看曲线、改模型，尽量在同一个工程里完成。

当前介绍基于 **v0.29.20**。项目仍在持续开发，欢迎提交可复现的问题、交互建议和小范围改进。

项目仓库：[awaqwqawa123/fuxian-spice-workbench](https://github.com/awaqwqawa123/fuxian-spice-workbench)。应用自有代码采用 MIT，既有第三方文件保留各自许可，详见 [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md)。

## 能做什么

| 工作环节 | 已有能力 |
| --- | --- |
| 原理图编辑 | 网格吸附、正交接线、器件移动与旋转、复制粘贴、网络标签、撤销与重做；可收起和调宽的项目、器件属性及助手侧栏 |
| 仿真与探针 | 瞬态、AC、DC 扫描、直流工作点和噪声分析；电压、电流、差分探针；真实 ngspice 计算 |
| 画布内波形 | 在原理图中放置多个波形图、调整位置和尺寸、配置曲线与视图；提供测量光标和放大查看功能 |
| SPICE 模型 | 查看和编辑模型源码、导入模型、管理自建库；模型与符号需要核对电气端序和兼容性 |
| 模型助手（可选） | 按型号搜索模型与规格书，保留来源和兼容诊断；条件允许时形成可审阅的近似模型候选 |
| 外部 AI 工具（可选） | 标准 stdio MCP 入口可读取项目、修改候选、校验电路并运行仿真；候选在网页中审阅、应用或撤销 |
| 文件与报告 | LTspice ASC / SPICE 文本网表的受支持子集交换；SVG 导出，以及包含电路、实际数据和运行条件的测试报告 |

### 把绘图体验放在前面

工作台以画布为中心。电路与波形可以同时出现在图纸里；顶栏提供探针和测量操作；不需要的侧栏可以收起。

v0.29.20 对未变化的器件、导线路径和只读几何结果增加复用，减少状态与聊天更新带来的重复绘制。这些优化没有降低仿真点数、求解精度或波形数据精度。顶栏“标记”按钮还可以一键隐藏探针图形，保留探针配置和测量结果。

### AI 通过可检查的工具参与

基础绘图和仿真不需要 AI 密钥。需要助手时，可以选择本机集成或兼容 stdio MCP 的客户端；Codex、Cursor、DeepSeek Harness 的安装、登录和能力取决于各自环境。

助手修改先生成候选，用户在工作台查看差异后应用。MCP 接口能够调用实际电路工具和仿真，但它本身不会让桌面聊天自动同步，也不会保证所有客户端的本机集成已经连通。

## 本地启动

准备 Git、Node.js 24 和 npm。取得公开仓库后，进入包含 `package.json` 的项目目录运行：

```bash
npm ci
npm run start
```

随后在浏览器打开 `http://localhost:3032/`。默认只监听本机地址。Windows 用户也可以运行项目中的 `run-workbench.cmd`。

开发服务使用：

```bash
npm run dev
```

开发服务默认在 3030 端口。草稿存储与访问地址、端口有关；切换地址前请导出需要保留的工程。

第一次体验可以按下面的顺序进行：

1. 新建或打开一个基础 RC 电路，修改阻容参数。
2. 设置瞬态或 AC 分析，放置电压探针并运行仿真。
3. 将波形图放入画布，选择需要显示的曲线。
4. 需要外部模型时再导入 `.model` / `.subckt`，核对引脚、来源与兼容性。

外部助手连接配置可在“设置”中查看，也可以在工作台运行后执行：

```bash
node scripts/workbench-mcp.mjs --print-config
npm run mcp:doctor
```

## 模型、符号与数据范围

公开版不附带维护者本机整理的原厂私有模型、PSpice / Capture / TINA 私有库，也不承诺包含原厂完整器件库。用户可以在获准使用的范围内导入自己的模型；下载得到的模型也需要遵守原作者条款。

`public/models/` 中可再分发的数据按各目录的来源说明和独立许可证保留。例如 KiCad 示例数据、Qucs-S 参考数据及社区测量模型使用不同许可，不能统一称为应用许可证下的模型。请保留对应 README、署名、许可证和转换记录。

能够解析和求解某个模型不代表它覆盖全部工作条件。社区参考模型、按规格书调整的近似模型与厂商原始模型会保留来源区别；涉及关键设计指标时，应核对数据手册、模型范围和实测结果。

## 当前边界

- LTspice ASC 和 SPICE 导入导出覆盖受支持子集；不提供 LTspice 全量格式兼容，也不支持 Multisim 原生工程文件。
- 各 SPICE 方言、加密模型、复杂宏模型及其依赖的支持情况不同；界面会给出解析或兼容性诊断，不能把每份厂商文件都直接视为可运行。
- 规格书通常不足以唯一确定完整动态模型。模型助手需要可追溯的参数、测试条件或适用模板；缺少依据时会保留缺口，生成候选需要审阅。
- AI、联网搜索、站点登录及桌面会话连接属于可选能力；依赖客户端版本、账号配置与本机环境。绘图、仿真与本地模型编辑可独立使用。
- 项目仍在开发；复杂原理图、极端布局、平台差异和交互细节欢迎用最小工程反馈。

## 开发与验证

```bash
npm run build
npm test
```

公开版提供精选回归集，覆盖绘图缓存、探针、波形操作以及真实 ngspice 求解。依赖私有原厂模型或真实项目附件的历史回归不随公开快照分发；这些检查通过不代表所有器件和工况已得到验证。

源码主要位于 `src/`，可选本机服务位于 `server/`，启动与诊断工具位于 `scripts/`，回归用例位于 `tests/`。绘图工作请阅读 `docs/drawing-guide.md`、`docs/drawing-patterns.md` 和 `docs/drawing-acceptance.md`；这些持续维护的规则来自对示例结构和已有绘图问题的分析，不代表逐份人工认证所有样例。
