# 伏线 · SPICE Workbench

[![Public source checks](https://github.com/awaqwqawa123/fuxian-spice-workbench/actions/workflows/public-source.yml/badge.svg)](https://github.com/awaqwqawa123/fuxian-spice-workbench/actions/workflows/public-source.yml)

**在一张画布上绘制电路、运行 ngspice、摆放波形图，并让可选 AI 助手通过工具参与设计。**

伏线是本地运行的网页电路仿真工作台，使用 React、TypeScript、Vite 和 WebAssembly 版 ngspice。它尝试把桌面原理图工具的交互和网页工作台结合起来：画电路、放探针、看曲线、改模型，尽量在同一个工程里完成。

当前介绍基于 **v0.30.3**。提供 Windows x64 解压运行包，也保留可自行构建的完整公开源码。项目仍在持续开发，欢迎提交可复现的问题、交互建议和小范围改进。

本次更新：器件库顶部自建库入口、SPICE 文件直接导入自建库、统一拓展器件弹窗、LTspice / PSpice 文件的受支持子集导入，以及紧凑布局和过渡动效。详见 [v0.30.3 更新说明](docs/open-source/RELEASE-v0.30.3.md)。

项目仓库：[awaqwqawa123/fuxian-spice-workbench](https://github.com/awaqwqawa123/fuxian-spice-workbench)。应用自有代码采用 MIT，既有第三方文件保留各自许可，详见 [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md)。

## 能做什么

| 工作环节 | 已有能力 |
| --- | --- |
| 原理图编辑 | 网格吸附、正交接线、器件移动与旋转、复制粘贴、网络标签、撤销与重做；可收起和调宽的项目、器件属性及助手侧栏 |
| 仿真与探针 | 瞬态、AC、DC 扫描、直流工作点和噪声分析；电压、电流、差分探针；真实 ngspice 计算 |
| 画布内波形 | 在原理图中放置多个波形图、调整位置和尺寸、配置曲线与视图；绘图区滚轮缩放波形双轴，中键拖动平移，提供测量光标和放大查看功能 |
| SPICE 模型 | 查看和编辑模型源码、导入模型、管理自建库；模型与符号需要核对电气端序和兼容性 |
| 模型助手（可选） | 按型号搜索模型与规格书，保留来源和兼容诊断；条件允许时形成可审阅的近似模型候选 |
| 外部 AI 工具（可选） | 标准 stdio MCP 入口可读取项目、修改候选、校验电路并运行仿真；候选在网页中审阅、应用或撤销 |
| 文件与报告 | 独立 `.fuxian` 工程分享与迁移；LTspice ASC / SPICE 文本网表的受支持子集交换；SVG 导出，以及包含电路、实际数据和运行条件的测试报告 |

### 把绘图体验放在前面

工作台以画布为中心。电路与波形可以同时出现在图纸里；顶栏提供探针和测量操作；不需要的侧栏可以收起。

v0.30.0 统一了顶栏、侧栏、表单和对话框的间距、控件与视觉层次，波形操作进一步集中。波形与器件共用可调宽的右侧属性区域，选中器件后切回对应参数；同屏波形区域也可以拖动分界调宽。

波形图框调整和报告等显示状态变化会复用未变化的电气计算结果，减少重复验证、几何计算与测量准备。普通运行默认使用已构建前端，避免源码开发服务的监视和按请求转换；内容哈希资源可长期缓存，入口重新验证，API 不缓存。这些优化没有降低仿真点数、求解精度或波形数据精度。顶栏“标记”按钮可以一键隐藏探针图形，保留探针配置和测量结果。

### AI 通过可检查的工具参与

基础绘图和仿真不需要 AI 密钥。需要助手时，可以选择本机集成或兼容 stdio MCP 的客户端；Codex、Cursor、DeepSeek Harness 的安装、登录和能力取决于各自环境。

助手修改先生成候选，用户在工作台查看差异后应用。MCP 接口能够调用实际电路工具和仿真，但它本身不会让桌面聊天自动同步，也不会保证所有客户端的本机集成已经连通。

## Windows 下载即用

从 [v0.30.3 发布页](https://github.com/awaqwqawa123/fuxian-spice-workbench/releases/tag/v0.30.3) 下载 **`Fuxian-0.30.3-Windows-x64.zip`**，完整解压到可写目录，然后双击 **`Fuxian.exe`** 或 **`启动伏线.cmd`**（英文入口 **`Launch-Fuxian.cmd`**），在原生启动器窗口点击 **“启动软件”**。服务准备好后会打开浏览器，默认地址为 `http://localhost:3032/`，只监听本机。

启动器会显示启动状态；失败时显示原因并可重试，已经运行时直接打开现有软件。关闭启动器窗口会保留后台服务。兼容旧入口 `Start-Fuxian.cmd` 仍可直接启动。

运行包自带已编译启动器、Node、依赖、已构建前端、ngspice WebAssembly 引擎及公开模型。基础绘图和仿真不需要安装 Node、执行 npm 或在首次启动时联网下载。`Stop-Fuxian.cmd` 停止本目录对应的服务；`Status-Fuxian.cmd` 查看状态。端口被其他程序占用时会报告错误，不会结束无关进程。

GitHub 自动提供的 **Source code (zip/tar.gz)** 是源码快照；普通 Windows 用户请下载上面命名的运行包。运行包不含维护者的私人厂商库、项目、账号和聊天；可选 AI 客户端仍需按各自要求安装、登录或配置。运行模式、打包与许可范围见 [Windows 便携包说明](docs/portable-windows.md)。

## 分享和迁移工程

v0.30.1 新增独立 `.fuxian` 工程文件。通过“文件 → 保存工程文件”、项目栏中的同名按钮或 Ctrl+S 保存；接收方通过“打开工程文件”打开为新项目，原有工程继续保留。旧版 JSON 工程仍可打开。

文件包含电路、工程内嵌 SPICE 模型及原始符号、探针、多套仿真配置、波形图配置和报告设置。打开后重新仿真生成波形；账号、密钥、聊天、历史求解结果和整份本机模型库不随文件迁移。外部模型依赖需要先完整导入工程，第三方模型保留各自来源和许可。详见 [独立工程文件说明](docs/project-file-format.md)。

## 从源码启动

准备 Git、Node.js 24 和 npm。取得公开仓库后，进入包含 `package.json` 的项目目录运行：

```bash
npm ci
npm run build
npm start
```

随后在浏览器打开 `http://localhost:3032/`。默认只监听本机地址。`npm start` 使用 `dist/` 中的生产前端；修改源码后重新执行 `npm run build` 并刷新浏览器。Windows 源码用户也可以运行 `run-workbench.cmd`，缺少构建时会先构建一次。

需要直接调试源码时使用：

```bash
npm run start:debug
```

调试与普通运行共用后台 API、项目格式和求解器，默认都在 3032 端口；先停止当前运行实例，再切换模式。调试模式关闭热更新，修改源码后手动刷新。草稿存储与访问地址、端口有关；切换地址前请导出需要保留的工程。

第一次体验可以按下面的顺序进行：

1. 新建或打开一个基础 RC 电路，修改阻容参数。
2. 设置瞬态或 AC 分析，放置电压探针并运行仿真。
3. 将波形图放入画布，选择需要显示的曲线。
4. 需要外部模型时再导入 `.model` / `.subckt`，核对引脚、来源与兼容性。

外部助手连接配置可在“设置”中查看，也可以在工作台运行后执行：

```bash
node scripts/workbench-mcp.mjs --print-config
npm run mcp:doctor
```

## 模型、符号与数据范围

公开版不附带维护者本机整理的原厂私有模型、PSpice / Capture / TINA 私有库，也不承诺包含原厂完整器件库。用户可以在获准使用的范围内导入自己的模型；下载得到的模型也需要遵守原作者条款。

`public/models/` 中可再分发的数据按各目录的来源说明和独立许可证保留。例如 KiCad 示例数据、Qucs-S 参考数据及社区测量模型使用不同许可，不能统一称为应用许可证下的模型。请保留对应 README、署名、许可证和转换记录。

能够解析和求解某个模型不代表它覆盖全部工作条件。社区参考模型、按规格书调整的近似模型与厂商原始模型会保留来源区别；涉及关键设计指标时，应核对数据手册、模型范围和实测结果。

## 当前边界

- LTspice ASC 和 SPICE 导入导出覆盖受支持子集；不提供 LTspice 全量格式兼容，也不支持 Multisim 原生工程文件。
- 各 SPICE 方言、加密模型、复杂宏模型及其依赖的支持情况不同；界面会给出解析或兼容性诊断，不能把每份厂商文件都直接视为可运行。
- 规格书通常不足以唯一确定完整动态模型。模型助手需要可追溯的参数、测试条件或适用模板；缺少依据时会保留缺口，生成候选需要审阅。
- AI、联网搜索、站点登录及桌面会话连接属于可选能力；依赖客户端版本、账号配置与本机环境。绘图、仿真与本地模型编辑可独立使用。
- 项目仍在开发；复杂原理图、极端布局、平台差异和交互细节欢迎用最小工程反馈。

## 开发与验证

```bash
npm run build
npm test
```

公开版提供精选回归集，覆盖绘图缓存、探针、波形操作以及真实 ngspice 求解。依赖私有原厂模型或真实项目附件的历史回归不随公开快照分发；这些检查通过不代表所有器件和工况已得到验证。

源码主要位于 `src/`，可选本机服务位于 `server/`，启动与诊断工具位于 `scripts/`，回归用例位于 `tests/`。绘图工作请阅读 `docs/drawing-guide.md`、`docs/drawing-patterns.md` 和 `docs/drawing-acceptance.md`；这些持续维护的规则来自对示例结构和已有绘图问题的分析，不代表逐份人工认证所有样例。
