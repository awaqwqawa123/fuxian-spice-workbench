# 独立工程文件 `.fuxian`

每个文件包含一个工程。通过“打开工程文件”加入本机项目列表，通过“保存工程文件”分享或迁移。工程文件与软件安装目录、浏览器端口、本机聊天标识相互独立；打开时分配新的本机项目身份，不覆盖原工程。

文件保存原理图布局、真实引脚与导线、器件参数、自定义源表达式、工程已嵌入的 SPICE 模型及其完整依赖、原符号几何与来源、探针、全部仿真配置、波形图框/视图/曲线/坐标/光标配置，以及报告设置。旧版 `.json` 工程仍可打开。

工程文件不包含求解器采样和历史仿真结果；接收端重新运行所选配置生成波形，避免把旧结果当作当前运行。报告中的既有修订元数据属于报告配置，不等同于可恢复的运行数据。账号、密钥、对话、桌面控制绑定、软件设置和整份本机模型库不参与打包。保留工程模型自身的来源、许可和署名；分享者需要遵守模型许可。

工程可保存为未完成草稿。缺少器件模型或存在未完成的仿真字段时，包内说明和打开提示会列出问题；它不保证草稿能够立即仿真。明确仍引用 `.include`、`.inc`、`.lib` 外部文件的模型拒绝打包，须先导入完整依赖。内置基础器件使用接收端伏线的内置定义；不会为了迁移把用户模型自动替换为近似模型。

## 格式版本 1

`.fuxian` 是一个 ZIP 容器，固定包含 `manifest.json`、`project.json` 和 `README.txt` 三个条目。`project.json` 使用现有严格项目解析器规范化；未知账户/运行字段不会写入。`manifest.json` 包含 `format: "fuxian-project"`、`version: 1`、生成时间、`resultPolicy: "configuration-only"`、项目字节数与 CRC32、内嵌模型/符号数量及导出时的草稿提示。打开时重新计算当前问题，清单中的文本不会作为执行指令。

输入文件最多 32 MiB，固定条目总展开大小最多 64 MiB。读取前核对 ZIP 中央目录和本地记录，限制条目、路径、压缩方式、展开大小、目录范围和重复名称，再解压并核对全部条目的 CRC32 和工程清单。版本 1 不支持 ZIP64、分卷、加密、ZIP 注释或中央目录扩展。任何条目都不解压到文件系统，也不读取或请求外部依赖路径。

CRC32 用于损坏检测，不提供防篡改签名或作者认证。格式版本未知、内容损坏、超限或字段错误时，不应用工程；用户可以保留原文件并修正来源。
