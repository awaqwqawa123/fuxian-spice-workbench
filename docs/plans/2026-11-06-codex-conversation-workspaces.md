# Codex 工程对话目录

用户希望电路助手连接 Codex 时使用独立文件夹，并适用于每个安装软件的用户。

默认在本机既有持久化数据目录内创建 workspaces，不依赖源码目录、开发账户或
写死的磁盘路径。目录名称只使用经过验证的 projectId 的 SHA-256，避免标题、
路径片段、Windows 保留名以及大小写重名。目录创建后通过 realpath 校验，拒绝
工程子目录链接到根目录之外。不可写、损坏设置或关联记录都以明确错误停止创建。

选择方案是每个工程一个稳定目录。仅一个全局目录会继续混合工程；按每条聊天
新建目录会拆散同工程的绘制与解释。主对话与解释通过同一个目录解析器读取
project-workspaces.json，短时串行化原子写入，避免并行建对话覆盖工程关联。
改变根目录用于未分配目录的新工程，既有工程保持原根目录，已有 Codex 绑定
只恢复，不改变 cwd。使用已有用户自定义目录作为根目录，并继续检查目录可写。

MCP 模式不代替外部客户端管理 cwd；设置清楚说明功能边界。外部 AI 仍通过
MCP projectId 选择工程。已有独立 CLI 会话继续使用自身 session workspace。

同时修正 DesktopControlManager 重连监听顺序：先移除旧监听再安装新监听，
避免 brokerFactory 重用实例时旧 disposer 清除新回调。现有完成任务重复回调
回归已确认返回明确失败且不重复执行工具。

验证：48 项定向测试全部通过，覆盖目录自动创建、工程隔离、并行分配持久化、
根目录切换、主/解释共用目录、路径穿越与符号链接越界拒绝、损坏记录、原有
聊天绑定及工具回放、设置草稿保留与 MCP 边界提示。TypeScript 构建检查通过。
