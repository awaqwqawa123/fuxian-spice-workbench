# 工作区固定 MCP 入口

工作台解压目录可能改变。AI 客户端继续执行同一条 stdio 命令；工作区移动后由用户重新关联，其他工作区或旧服务不能接走原配置的请求。工程与会话数据不属于 MCP 配置。

采用每位用户一套版本化的桥程序，每个工作区一条关联。工作台创建随机 UUID，保存于与电路数据同行的 `.desktop-circuit/workspace-identity.json`。窗口启用入口时，后端只取自身生成的连接文件；终端可在保留工作区标识的前提下显式关联新位置。桥读取对应连接文件，预先向其本机端口确认工作区，再发送工具请求；服务在执行工具前再次检查工作区。认不出的标识、故障的关联状态以及不支持校验的端口均停止转发。

直接让客户端执行解压目录里的桥，上手简单但移动后必须同时编辑所有客户端。使用固定端口、寻找最近运行的实例或自动发现后改写目标地址，会在多实例时变得不确定。固定桥把客户端入口与安装位置分开；已启用后增加一份运行时占用，升级桥内部协议时应考虑已导出的客户端配置兼容性。沿用原先只接受回环地址的授权方式；关联和导出的配置不保存令牌。

验证覆盖实际 HTTP 服务及复制到用户目录的 Node 进程：两个独立实例并存、端口重启、保留工程与标识后移动、错误标识或串用连接文件、设置页显式启用和重连提示。外部软件自己的安装、登录、配置重载和工具发现仍单独验收。
